# backend/CLAUDE.md — правила бэкенда

Уточняет корневой [`CLAUDE.md`](../CLAUDE.md) для `backend/`. Общие правила (язык, роль, вопросы, git) — там.

## 1. Стек и структура

Python 3.12 + FastAPI.

| Папка | Что внутри |
|---|---|
| `backend/api/` | основной API: участники, лоты, заявки, пулы, залог, правила продавца |
| `backend/ml-service/` | подбор пула, маршрут, детекторы риска, вызовы LLM |
| `backend/ruff.toml` | общие правила ruff для обоих сервисов |

- Зависимости — предпочтительно [uv](https://docs.astral.sh/uv/) + `pyproject.toml` в каждом сервисе. Версии закрепляем. Новую зависимость — сначала согласовать (корневой `CLAUDE.md` §5).
- Каждый сервис должен собираться своим `Dockerfile` в своей папке: на это рассчитан `docker-compose.yml`.

## 2. Команды

Из папки сервиса (`backend/api` или `backend/ml-service`):

| Задача | Команда |
|---|---|
| Линтер | `sh ../../scripts/ruff.sh check .` (автоисправление: `--fix`) |
| Форматирование | `sh ../../scripts/ruff.sh format .` |
| Тесты | `sh ../../scripts/pytest.sh .` |

`scripts/ruff.sh` запускает ruff той же версии, что и CI. Pre-commit делает линтер и форматирование сам, pre-push — тесты.

## 3. Контракт с фронтендом

- Все маршруты API — **под префиксом `/api`** (`/api/lots`, `/api/pools/{id}`). Dev-сервер фронта проксирует `/api/*` на `localhost:8000` без изменения пути. Поэтому CORS в разработке не нужен.
- API на порту **8000**, ML-сервис — на **8001** (как в `docker-compose.yml`). Фронтенд ходит только в API, в ML-сервис — только API.
- Запросы и ответы описываются Pydantic-моделями. Нет «сырых» dict в ответах, нет `Any` без необходимости.
- Ошибки — осмысленные HTTP-коды и понятное сообщение. Не подменяй ошибку пустым ответом.
- Если меняется контракт (поля, формат) — предупреди: это ломает фронтенд.

## 4. Бизнес-логика: формулы и LLM

Это ядро продукта. Требования — в PRD, разделы «Формулы и подбор пула» и «Интеграция Claude».

- **Рейтинг, залог, допуск, подбор пула, маршрут и деление доставки — чистые функции** без ввода-вывода, с типами и **обязательными тестами**. В тестах проверяем граничные значения (например, рейтинг 39/40/59/60 в таблице залога).
- Числа, которые PRD помечает как параметры (минимальный залог новичка с поручителем 3% или 5%, тариф доставки), — константы в одном месте, а не магические числа по коду.
- **LLM только объясняет и разбирает текст**, решения не принимает. По PRD у неё ровно три задачи:
  1. объяснить залог, допуск, риск и пул простыми словами — с цифрами, которые уже посчитал бэкенд;
  2. разобрать текст продавца в JSON-правило по схеме — продавец подтверждает правило;
  3. сформулировать риск по сигналам детекторов.
- Вызовы LLM: температура 0, структурированный вывод по JSON Schema. Ответ модели валидируем Pydantic-моделью. Если ответ не прошёл валидацию — ошибка, а не догадка.
- Ключ API и имя модели — из переменных окружения, с примером в `.env.example`. В тестах LLM подменяется заглушкой: тесты не ходят в сеть.
- Данные ГНК и судов, эскроу, клиринг — заглушки. Их интерфейс должен позволять потом подставить настоящую интеграцию.

## 5. Тесты

- pytest, файлы `test_*.py`. Тесты рядом с кодом или в `tests/` сервиса — главное, одинаково внутри сервиса.
- Формулы покрываем полностью (§4). Эндпоинты — через `TestClient` FastAPI: успешный путь и основные ошибки.
